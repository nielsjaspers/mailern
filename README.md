# Mailern

A native SwiftUI email workflow prototype for iPhone and iPad, with fictional mail across four accounts. Requires iOS 18 or later and Xcode 26 or later.

Open `Mailern.xcodeproj`, select the Mailern scheme and your device, then choose your development team under Signing & Capabilities and run. No packages or provider credentials are needed.

## Try the workflow

- Each mailbox has a Filter toggle in the top toolbar. When active, the toggle stays on the right and its capsule expands to the left with “Filtered by” and the current criteria. Tap the criteria or its arrow to open Filters. The button toggles filtering without clearing its settings. Choose any combination of accounts, All/Unread/Read in Inbox and Snoozed, Only drafts in Inbox and Snoozed, or Only sent in Settled. Conditions combine with AND; selected accounts combine with OR. Sent matches conversations containing an outgoing message. Settings persist separately for each mailbox. Search and Select All use the filtered results; the Inbox badge still counts all unread conversations. Inbox keeps pinned items first, Snoozed orders by return time, and Settled keeps newest first.
- Each row shows a sender avatar, everyone who wrote in the conversation, a message count for threads, the subject, and one line of the latest message. Your own messages show as Me; sent-only conversations show their recipients.
- Opening a conversation marks it read and keeps it in its current section. The latest message is open; earlier messages fold to compact headers. Tap a message header to open or fold it.
- Swipe left for Settle or Snooze. In Settled, swipe left to restore.
- Swipe right for Read/Unread and Pin. A full right swipe toggles read status outside Settled.
- Hold a conversation for a compact, scrollable preview with the tools visible. Drag the tools downward to enlarge the card; drag upward to shrink it and reveal the menu again. Tap a reply shortcut or menu action. The preview shows the latest message and counts the earlier ones. Reading the preview preserves read status; tapping it opens the conversation, where earlier messages can be opened.
- Use the thread's Reply menu for Reply, Reply All, and Forward of the latest message. Each open message has its own reply button and a menu with the same three actions, which quote and address that message. A reply started from a message keeps its own draft, separate from the toolbar's reply draft. Sending a reply adds a message and settles that conversation. New messages and forwards appear in Settled.
- Use More → Demo at the top left to receive new mail, receive a reply to any conversation, or reset all demo data.
- Snooze for one or three hours, this evening, tomorrow, next week, or a custom date. Options are sorted by return time; past evening times are hidden. Next week defaults to Monday at 09:00. Use Snooze settings in More or the snooze picker to change the presets. Settings persist across launches and only affect future snoozes. Expired snoozes return while the app is active, or when it next opens. The prototype does not run a background mail service or send notifications.
- Incoming replies immediately return a conversation to Inbox as unread, including from Snoozed and Settled. Settling marks conversations read. Settled conversations cannot be marked unread. Pins remain independent of workflow status.
- The Undo card disappears after five seconds. Each new action restarts that window. Undo reverses the most recent workflow move, including the prior read status when undoing Settle. Incoming mail, sending, and attaching a reply draft to a pending workflow move invalidate Undo so it cannot hide a newer message.
- Search covers the current section's subjects, senders, accounts, and message bodies.

Messages, workflow state, and drafts are saved as atomic JSON in the app's Application Support directory. Attachment bytes live in separate files, so mailbox actions only rewrite small metadata. Loads map attachment files on demand, and unreferenced files are removed when storage is updated. Draft JSON encoding and writes run in an ordered background queue, and dismissal waits for successful persistence. The composer uses native sheet transitions, recipient and sender fields, and a rich text editor. Use Aa for text styles, fonts, color, lists, alignment, and indentation. Formatting participates in native Undo and Redo. Formatting uses Apple's native panel. The paperclip imports files or photos, with a 25 MB total limit and native file previews. Save Draft and Delete Draft are in the close button's menu. Swiping the sheet away saves an edited draft before dismissal. If saving fails, the editor stays open with its contents intact. Unreadable draft storage is protected from overwrite; the Drafts storage alert offers Retry. Drafts have an orange row tint and a composer icon. Reply drafts stay with their existing conversation in its current mailbox; new messages and forwards have separate rows in Inbox until snoozed. Open the row to read the draft at the bottom, then use Edit draft or Discard draft. Standalone drafts support Pin and Snooze through the configured swipe actions and their reader. Their Settle action asks to discard the draft or cancel. Conversations with drafts retain Pin, Snooze, Restore, and Read/Unread outside Settled. Settling a conversation with drafts asks to discard those drafts or cancel, including in bulk selection. Failed draft writes preserve the drafts and prevent settling. Snoozed drafts return to Inbox when due. Draft text and recipients are included in search. If storage remains unavailable after dismissing the alert, use More → Retry loading drafts. Replies include an editable quote and settle the source conversation when sent; forwards create a separate settled conversation. All sending remains simulated. The reader displays local text, rich outgoing messages, and attachments, but does not render arbitrary HTML email.

Drag the composer content to hide the keyboard without closing the message. Tap any field to continue editing.

## Code

`Mailern/Core` contains conversation models, demo messages, and the observable store. `ConversationPersistence` separates storage from state changes. `Mailern/Views` contains the native SwiftUI screens. Workflow status does not map to a provider folder or label. No provider integrations or backend are included.

Run `scripts/check-workflow.sh` for isolated state and persistence checks. It creates a unique temporary data file, separate from the app's demo data.

Prototype refinements use patch versions. Increment the build number for each distributed build; reserve minor versions for larger milestones.

Run `scripts/check-ui.sh DISPOSABLE_SIMULATOR_ID` for the full suite. It builds once and uses four additional disposable Simulator workers plus the supplied fixture Simulator for duration-balanced batches. The two native picker tests stay on the fixture Simulator, which also runs ordinary cases so it does not sit idle after imports. After worker creation or cold boots, the picker tests finish first, then at most three worker batches run at a time. This limits startup contention while the workers become ready for later runs. The first run creates the workers. Later runs reuse them to avoid repeated Simulator setup. Workers stay booted between runs to keep reruns fast. Run `scripts/check-ui.sh DISPOSABLE_SIMULATOR_ID --stop` to release their running resources. They remain in the Simulator device list; delete them there when no longer needed. The script reports the total time, including build and fixture setup, and merges every batch into one result bundle. Pass an additional-worker count from 1 to 10 as the second argument. Use fewer workers on machines with less memory. Stop the pool before reducing its worker count. Each UI test has its own class so the runner can balance individual tests using recorded durations. Each test uses separate mail, draft, attachment, and preference storage; relaunches within a test preserve that storage. The long-thread test seeds its history directly, then drives a real incoming reply. Each batch checks that every expected case ran exactly once, with no failures or skips, before the merged result is validated. Automatic screenshot attachments are disabled. UI failures capture the current screen. Named captures and screenshot assertions still run; successful named attachments are discarded. Product → Test in Xcode also permits parallel execution, but native picker tests require the fixture setup from the script. For the composer suite, run `scripts/check-composer-ui.sh SIMULATOR_ID` on a booted disposable Simulator. The script installs the app, copies the fictional file fixture into its Documents directory, imports a sample image into Photos, and tests file and photo import, formatting, draft recovery, reply/forward sending, and swipe dismissal, including forced storage failures. Native editor tests check mixed formatting and rich-text persistence.

The checked-in Xcode project works directly. After adding source files, regenerate it with `python3 scripts/create-project.py`. Edit `Mailern/AppIcon.icon` in Icon Composer. Its three vector groups separate the rounded upper wing, rear wing, and body, with the upper wing in front. Xcode compiles the layered icon and its appearance variants directly from this file. Building the icon requires Xcode 26 or later.

## Remote development installation

`scripts/package-demo.sh TEAM_ID` archives and exports a development-signed IPA using an existing Xcode signing account/profile. The iPhone must be registered in that profile and have Developer Mode enabled. A development-signed app expires with its provisioning profile.

`scripts/serve-demo.py HTTPS_BASE_URL --source-revision BUILD_COMMIT_HASH` creates an OTA manifest and a plain install page with light and dark themes in `build/install`. Capture the Git commit hash when creating the archive, rather than reading the current checkout when publishing an older build. Add `--uncommitted-changes` if the build includes uncommitted source changes. The generator checks that the IPA and archive have matching bundle identifiers, versions, and build numbers. It omits the optional changelog because previous builds do not have reliable source history recorded. Serve only the installation directory over trusted HTTPS, such as a dedicated Tailscale Serve path. Open its page in Safari on the registered iPhone with Tailscale connected. The computer serving the files must remain awake and connected.

Pass an optional output directory as the second argument to prepare a separate install page for a PR build without replacing an existing installation page. Use `--archive PATH` and `--ipa PATH` for builds outside the default archive and export directories.

Settings in the More menu includes snooze preferences and Labs. Compose is at the bottom right by default while preserving native tabs. iOS 27 uses the system's prominent trailing tab; earlier versions use a native bottom toolbar. Labs can assign the Inbox pull-down gesture to Search or New email. This experiment is off by default and persists locally. Pull actions require iOS 18 or later. Start a pull while the Inbox is stationary at the very top. Pull farther to fill the ring; a soft tap and brief pulse indicate readiness. Move back up to cancel or pull down again to rearm before releasing. Search opens immediately on release. Compose uses the same native transition as its button.

Labs → Swipe actions configures the full-swipe action and an optional additional button separately for left and right swipes. Choose Settle / Restore, Read / Unread, Snooze, Pin / Unpin, or None. The same configuration applies in all mailboxes, persists locally, and can be reset to the defaults.

Use Select at the top of any mailbox for bulk actions. Select All selects the current search results and changes to Deselect All when every result is selected. The bottom toolbar offers Settle or Restore, Snooze, and a Mark menu with contextual Read/Unread and Pin/Unpin actions. Mixed selections offer Mark Read and Pin. Settled omits Read/Unread actions. In Snoozed, Mark also offers Restore to Inbox. Selection never marks mail read. Cancel exits selection; cancelling the snooze picker keeps the selection. Undo reverses the entire batch.
