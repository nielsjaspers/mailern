# Development

Run `scripts/check-workflow.sh` for isolated state and persistence checks. It creates a unique temporary data file, separate from the app's demo data.

Run `scripts/check-ui.sh DISPOSABLE_SIMULATOR_ID` for the full suite. It builds once, installs the app on that one Simulator, copies the fictional file fixture into the app's Documents directory, imports a sample image into Photos, and runs every UI and editor test serially. It never creates or boots other Simulators, so memory use stays at one Simulator plus the test runner. The runner shuts the Simulator down when it exits, including after a failed or canceled run. Pass `--keep-booted` for a warm rerun after a successful run, and use `scripts/check-ui.sh DISPOSABLE_SIMULATOR_ID --stop` to shut it down later or after a force-kill. Each run checks that every selected test method ran exactly once, with no failures or skips, and a case that hangs fails after two minutes instead of stalling the run. Each test uses separate mail, draft, attachment, and preference storage, so tests do not reset settings when they finish; relaunches within a test preserve that storage. In script runs, DEBUG fixture plumbing resets stores, preferences, and navigation between independent cases in the same app process. It does not close a sheet presented from a thread, so each case closes what it presents. After a failed case, the next case starts a fresh app process. A request/session acknowledgment verifies each reset. Every later launch within a case still restarts the actual process and checks that its process identity changed. Script runs turn off UIKit animations in the app, because XCTest waits for the app to settle after every action; this roughly halves the run. Timers, such as the Undo window, keep their real durations. With animations off, a script run cannot catch a bug that only shows during a transition, such as a row ghosting, a card jumping, or a tap lost while a sheet closes. After changing a transition, run the affected tests with `MAILERN_TEST_ANIMATIONS=on` and `--only-testing`. Without the script's control environment, tests use normal XCTest launches with animations. The long-thread test seeds its history directly, then drives a real incoming reply. The script disables OS activity logs in the test app to reduce Simulator logging overhead. Automatic screenshot attachments are disabled. Issues recorded on the main thread attach the current screen directly to the issue, so failure screenshots are included in `xcresulttool export attachments --only-failures`. UI tests check what only the running app shows: gestures, layout, native pickers, and navigation. Store and filter logic belongs in `scripts/check-workflow.sh`, which runs in seconds. For a focused run, pass `--only-testing XCTestIdentifier` and repeat it to select multiple tests. Product → Test in Xcode skips the script's fixtures, so the file and photo import tests fail there.

For the composer suite, run `scripts/check-composer-ui.sh DISPOSABLE_SIMULATOR_ID`. It tests recipient search, text selection and formatting, keyboard dismissal, minimizing and resuming drafts, forced draft storage failures, Undo Send, and file and photo import. Native editor tests check mixed formatting and rich-text persistence.

The checked-in Xcode project works directly. After adding source files, regenerate it with `python3 scripts/create-project.py`.

Edit `Mailern/AppIcon.icon` in Icon Composer. Its three vector groups separate the rounded upper wing, rear wing, and body, with the upper wing in front. Xcode compiles the layered icon and its appearance variants directly from this file. Building the icon requires Xcode 26 or later.
