# How Mailern behaves

This is the detailed behavior of the app. Keep it in sync when behavior changes.

## Workflow

- Each mailbox has a Filter toggle in the top toolbar. When active, the toggle stays on the right and its capsule expands to the left with “Filtered by” and the current criteria. Tap the criteria or its arrow to open Filters. The button toggles filtering without clearing its settings. Choose any combination of accounts, All/Unread/Read in Inbox and Snoozed, Only drafts in Inbox and Snoozed, or Only sent in Settled. Conditions combine with AND; selected accounts combine with OR. Sent matches conversations containing an outgoing message. Settings persist separately for each mailbox. Search and Select All use the filtered results; the Inbox badge still counts all unread conversations. Inbox keeps pinned items first, Snoozed orders by return time, and Settled keeps newest first.
- Each row shows a sender avatar, everyone who wrote in the conversation, a message count for threads, the subject, one line of the latest message, and the account name with its color. Your own messages show as Me; sent-only conversations show their recipients.
- Opening a conversation marks it read and keeps it in its current section. The latest message is open and uses the full width of the screen. Folded messages show their sender, date, and first line on the page, with a line between messages; tap one to open it, or tap an open message's sender to fold it. Conversations with more than four messages show the first message and the last two, with one row for the messages between them. Under an open message's sender, tap "to me" for the full addresses and date. Quoted history at the end of a reply folds behind a "…" button. Mailern only folds the quote its own composer added: the "On … wrote:" line followed by exactly the message the reply answers, with nothing after it and no formatting added to it, such as bold, strikethrough, or centering. Everything else always shows, including quotes written by other mail clients.
- Swipe left for Settle or Snooze. In Settled, swipe left to restore.
- Swipe right for Read/Unread and Pin. A full right swipe toggles read status outside Settled.
- Hold a conversation for a compact, scrollable preview with the tools visible. Drag the tools downward to enlarge the card; drag upward to shrink it and reveal the menu again. Tap a reply shortcut or menu action. The preview shows the latest message first; scroll down to read the earlier messages, newest to oldest. Reading the preview preserves read status; tapping it opens the conversation, where earlier messages can be opened.
- Use the thread's Reply menu for Reply, Reply All, and Forward of the latest message. Each open message has its own reply button and a menu with the same three actions, which quote and address that message. A reply started from a message keeps its own draft, separate from the toolbar's reply draft. Sending a reply adds a message and settles that conversation. New messages and forwards appear in Settled. Sent mail waits 10 seconds before it goes out: tap Undo on the Sending banner to reopen it in the composer. Settings → Undo send sets the delay to Off, 5, 10, or 20 seconds.
- More → Settings → Mail Server connects to mailern-server. Its mail, drafts, and preferences are kept apart from the demo mail; Use Demo Mail switches back. Accounts come from the server: names, colors, and signatures can change on the phone, but adding and deleting accounts happens in the server's config. Sent mail goes out through the server and is refused, back to the composer or Drafts, when the server cannot send it. Messages show as text until opened; opening one loads its HTML.
- Use More → Demo at the top left to receive new mail, receive junk mail, receive a reply to any conversation, or reset all demo data.
- Under More → Demo → Large Mailbox, open 10,000 or 20,000 fictional conversations. Each size has its own mail, drafts, and preferences, and is generated the first time you open it. The app reopens the selected mailbox after a restart. Use Return to Demo Mail to switch back to your original mail and settings. Demo Mail continues processing due mail. A fixture processes its due mail while selected.
- Snooze for one or three hours, this evening, tomorrow, next week, or a custom date. Options are sorted by return time; past evening times are hidden. Next week defaults to Monday at 09:00. Use Snooze settings in More or the snooze picker to change the presets. Settings persist across launches and only affect future snoozes. Expired snoozes return while the app is active, or when it next opens.
- Hold Send in the composer for Send Later and Remind Me If No Reply. Both use the snooze presets or a custom date. Scheduled mail is listed under Mailboxes → Scheduled and as a card in its thread, with Edit, Send Now, and Cancel Send. Edit and Cancel Send return it to Drafts. Scheduled mail is sent while the app is active, or when it next opens. A conversation settles when its reply is sent, not when it is scheduled.
- With a reminder, sent mail waits in Snoozed until the reminder time. A reply ends the reminder. When the time passes without one, the conversation returns to Inbox marked No reply. Moving the conversation by hand, including to Trash or Junk, also ends the reminder. Undo restores it.
- In More → Settings → Notifications, enable reminders for snoozed mail, No Reply, and Send Later. Settle and Snooze Again (one hour) open Mailern. Settle asks before discarding a saved reply draft. A Send Later alert prompts you to open Mailern so it can send the message. Mailern schedules up to 64 pending alerts and fills open slots when you use the app. The app icon badge counts all unread Inbox conversations in the selected demo mailbox, even with a filter active. While Mailern is closed, scheduled conversation alerts update the badge. Open Mailern to refresh it after the selected mailbox’s last scheduled conversation alert. You can change alerts and badges separately in iOS notification settings.
- Mute a conversation from the thread's More actions. Replies to a muted conversation join it without moving it or marking it unread, and muted rows show a bell icon. A reply that answers a reminder on a muted conversation settles it quietly.
- Incoming replies immediately return a conversation to Inbox as unread, including from Snoozed and Settled, unless it is muted. Settling marks conversations read. Settled conversations cannot be marked unread. Pins remain independent of workflow status.
- The Undo card disappears after five seconds. Each new action restarts that window. Undo reverses the most recent workflow move, including the prior read status when undoing Settle. Incoming mail, sending, and attaching a reply draft to a pending workflow move invalidate Undo so it cannot hide a newer message.
- Search covers subjects, senders, accounts, and message bodies. Queries of three or more characters use a full-text index, so any part of a word matches. A picker at the top of the results switches between This section, which searches the open mailbox, and All mail, which searches Inbox, Snoozed, and Settled together, in sections that name each result's mailbox, newest first within each. All mail leaves out Junk and Trash and ignores filters, and bulk selection is unavailable. Closing search returns to This section.
- In the thread reader, the up and down chevrons open the previous or next conversation in the list you came from. Search results show a passage from the matching message and open it even when it is folded. Choose **More actions → Find in conversation** to step through highlighted passages.
- Settings → After settling chooses what a thread shows after Settle: Return to list (the default) or Open next conversation. The next conversation is the one below in the list you opened the thread from, including its search and filter, or the one above when it was the last. Back returns to the list.
- Settle, Snooze, Pin, Read/Unread, Move to Trash or Junk, and Restore play a light haptic, wherever you start them. Opening a conversation and incoming mail do not.
- Settings → Accounts lists the accounts. Tap one to change its name, address, color, or signature, or to delete it. Deleting an account removes its conversations and drafts after a confirmation; the last account cannot be deleted. Add Account creates another fictional account.
- New messages, replies, and forwards start with the sending account's signature, above any quote. Changing From in a new message or forward swaps the signature, unless you edited it.
- Scheduled, Junk, and Trash are under Mailboxes in the More menu at the top left, not in the tab bar. Each opens on the current tab's stack. Move a conversation to Trash from the thread toolbar, the peek menu, bulk selection, or a Trash swipe action configured in Settings. Move it to Junk from the thread's More actions or bulk Mark. Conversations keep their workflow status while in Junk or Trash, so Restore and Not Junk return them to the section they left. Undo reverses the move. Conversations with reply drafts ask to discard the drafts first. Scheduled replies stay scheduled, but deleting a conversation permanently also discards them.
- Move to Junk and Not Junk affect only the selected conversation. Open an incoming message's actions menu to block or unblock its sender. The same menu opens Sender History, which lists conversations with that address across accounts and mailboxes and also lets you block or unblock it. Settings → Blocked Senders lists all blocked addresses, including blocks saved by earlier builds.
- New mail from a blocked address goes to Junk. A blocked reply goes to Junk without moving the original conversation. Deleting junk mail keeps the block in effect. New replies from other senders follow the conversation: a reply can return a conversation from Trash to Inbox, while a conversation in Junk stays there until restored.
- Swipe left in Junk or Trash to restore or delete permanently. Select supports both actions in bulk. Empty Trash and permanent deletion ask for confirmation and cannot be undone. Conversations are deleted automatically 30 days after they move to Trash, while the app is active or when it next opens.

## Settings, swipe actions, and selection

Settings in the More menu includes accounts, snooze preferences, swipe actions, the Undo Send delay, what to show after Settle, and Labs. Compose is at the bottom right by default while preserving native tabs. iOS 27 uses the system's prominent trailing tab; earlier versions use a native bottom toolbar. Labs can assign the Inbox pull-down gesture to Search or New email. This experiment is off by default and persists locally. Pull actions require iOS 18 or later. Start a pull while the Inbox is stationary at the very top. Pull farther to fill the ring; a soft tap and brief pulse indicate readiness. Move back up to cancel or pull down again to rearm before releasing. Search opens immediately on release.

Settings → Swipe actions configures Full Swipe, Additional Action 1, and Additional Action 2 separately for left and right swipes. Each slot is optional. With Full Swipe set to None, the additional actions remain available as buttons without triggering on a full swipe. Choose Settle / Restore, Read / Unread, Snooze, Pin / Unpin, Move to Trash, or None. On standalone drafts, Move to Trash asks to discard the draft. The same configuration applies in all workflow mailboxes, persists locally, and can be reset to the defaults. Junk and Trash keep their Restore and Delete Permanently actions.

Use Select at the top of any mailbox for bulk actions. Select All selects the current search results and changes to Deselect All when every result is selected. The bottom toolbar offers Settle or Restore, Snooze, Move to Trash, and a Mark menu with contextual Read/Unread, Pin/Unpin, and Move to Junk actions. Mixed selections offer Mark Read and Pin. Settled omits Read/Unread actions. In Snoozed, Mark also offers Restore to Inbox. Selection never marks mail read. Cancel exits selection; cancelling the snooze picker keeps the selection. Undo reverses the entire batch.

## Composer and drafts

The composer is a panel that slides up over the screen, with native recipient and sender fields and a rich text editor. Use Aa for text styles, fonts, color, lists, alignment, and indentation. Formatting participates in native Undo and Redo. Formatting uses Apple's native panel. The paperclip imports files or photos, with a 25 MB total limit and native file previews. Save Draft and Delete Draft are in the close button's menu. Pull the composer down by its top to browse your mail. The panel then rests behind the tab bar or the reader toolbar, with its subject and recipients showing above it. Tap it or drag it up to continue at the same position in the message body. Minimizing another draft takes that place, and the previous draft stays in Drafts. The panel saves its edits on the way down. If saving fails, it comes back up with its contents intact.

Drag the composer content to hide the keyboard without closing the message. Tap any field to continue editing.

Tap Add recipient beside To to browse known senders. Search recipients by name or email address, then tap a result to add it to To. Tap Contacts to choose a specific email address from the iPhone contact picker. New messages use the single account selected by an active Inbox filter or the Default From account in Settings. Replies and forwards use the conversation’s account.

Unreadable draft storage is protected from overwrite; the Drafts storage alert offers Retry. Drafts have an orange row tint and a composer icon. Reply drafts stay with their existing conversation in its current mailbox; new messages and forwards have separate rows in Inbox until snoozed. Open the row to read the draft at the bottom, then use Edit draft or Discard draft. Standalone drafts support Pin and Snooze through the configured swipe actions and their reader. Their Settle action asks to discard the draft or cancel. Conversations with drafts retain Pin, Snooze, Restore, and Read/Unread outside Settled. Settling a conversation with drafts asks to discard those drafts or cancel, including in bulk selection. If saving the draft change fails, the drafts and conversations stay in place. Once the mail move commits, SQLite records which drafts were discarded so recovery can finish after relaunch. Snoozed drafts return to Inbox when due. Draft text and recipients are included in search. If storage remains unavailable after dismissing the alert, use More → Retry loading drafts.

Replies include an editable quote and settle the source conversation when sent; forwards create a separate settled conversation. Demo mail simulates sending. Connected accounts send through the mail server.

## Reader

The reader displays local text, rich outgoing messages, HTML mail, and attachments. HTML mail runs in a web view with JavaScript off and no stored cookies. Remote images, styles, and fonts stay blocked until you tap Load images, because senders use them to see when mail is opened. Embedded `data:` images always show. Frames and redirects never load. Mail laid out for a fixed width is scaled to fit. HTML mail spans the full width of the screen, with the page's own margins. Mail that styles itself for dark mode follows the system appearance; other mail keeps a white page in dark mode. The demo Sample Weekly newsletter shows the light-only case with a blocked tracking pixel, and the snoozed workshop message shows the dark-aware case. Web links, email addresses, and phone numbers in messages are tappable. A `mailto:` link opens a new message with its recipients, subject, and body; other links open in the system's default app, such as the browser for web links. Plain-text mail shows as written and is not read as Markdown.

## Storage and sync

Messages, workflow state, accounts, and blocked senders are saved in a SQLite database in the app's Application Support directory, with one row per conversation, so a mailbox action rewrites only the conversations it changed. A trigram full-text index in the same database covers search. Drafts and scheduled mail are saved together as atomic JSON. Each sent message keeps its draft's ID, so if the draft cannot be removed after sending, the next attempt removes it without sending a second copy. Scheduled mail that cannot be sent returns to Drafts with an alert. Attachment bytes live in separate files, so neither store rewrites them. Loads map attachment files on demand, and unreferenced files are removed when storage is updated. Draft JSON encoding and writes run in an ordered background queue, and dismissal waits for successful persistence.

`Mailern/Core` contains conversation models, demo messages, and the observable store. `ConversationPersistence` separates storage from state changes; `SQLitePersistence` uses the SQLite library that ships with iOS, so no packages are needed. `Mailern/Views` contains the native SwiftUI screens. Messages carry Message-ID, In-Reply-To, and References headers, and incoming mail joins the conversation in the same account that holds the message it answers. Workflow status is local for demo mail. For server mail, Settle archives on the provider, Pin flags, and Trash and Junk move the thread, while Snooze, mute, and reminders stay in Mailern, so snoozed mail remains in the provider's inbox. `RemoteMail.swift` merges syncs from mailern-server: each conversation records the state the server last confirmed, so a local change keeps its place until the server confirms it, while new messages arrive at once. `MailServer.swift` runs the sync while the app is open. The server maps the workflow to the provider's mailboxes; see [server/README.md](../server/README.md).
